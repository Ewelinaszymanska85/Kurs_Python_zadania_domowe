"""
CI/CD i GitHub Actions
Zadanie 16 - Secrets Management

Cel zadania:
Przećwiczenie bezpiecznego wykorzystania danych poufnych
w GitHub Actions przy użyciu GitHub Secrets.

Wykonanie:

1. W folderze:

   .github/workflows/

   utworzyłam plik:

   ad_16_secrets_management.yml

2. Workflow uruchamiany jest ręcznie za pomocą:

   workflow_dispatch

3. W ustawieniach repozytorium GitHub przeszłam do:

   Settings
   -> Secrets and variables
   -> Actions
   -> New repository secret

4. Utworzyłam secret o nazwie:

   API_KEY

5. Wartości secretu nie umieszczałam bezpośrednio
   w kodzie ani w pliku YAML.

6. W workflow odwołałam się do secretu za pomocą:

   ${{ secrets.API_KEY }}

7. Secret został przekazany do zmiennej środowiskowej:

   env:
     API_KEY: ${{ secrets.API_KEY }}

8. Workflow sprawdza, czy API_KEY został prawidłowo
   przekazany.

9. Dodałam również maskowanie wartości za pomocą:

   echo "::add-mask::$API_KEY"

10. Następnie workflow symuluje proces deploy,
    który posiada dostęp do API_KEY.

11. Prawdziwa wartość API_KEY nie została zapisana
    w repozytorium.

Rezultat:

Secret:
API_KEY

Miejsce przechowywania:
GitHub Repository Secrets

Dostęp w workflow:
secrets.API_KEY

Deploy:
symulowany

Wnioski:

Dane poufne, takie jak klucze API, tokeny i hasła,
nie powinny być zapisywane bezpośrednio w kodzie.

GitHub Secrets umożliwia bezpieczne przekazywanie
takich wartości do workflow GitHub Actions.

Przećwiczone elementy:
- GitHub Secrets,
- secrets.API_KEY,
- env,
- maskowanie secretów,
- workflow_dispatch,
- bezpieczeństwo CI/CD,
- symulacja deploy.
